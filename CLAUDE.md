па# SUP Shop — контекст проекта для Claude Code

## Что это за проект

Учебно-портфолио проект: интернет-магазин SUP-досок (sup-shop), backend на
Spring Boot + PostgreSQL, frontend на React. Конечная цель — трудоустройство
на позицию Junior/Junior+ Full Stack Java Developer. Проект должен выглядеть
профессионально на собеседовании, но при этом каждая строчка кода должна
быть реально понята автором, а не просто скопирована.

## ГЛАВНОЕ ПРАВИЛО РАБОТЫ — читай перед любым действием

Автор проекта — не опытный разработчик, а человек, который учится Java/Spring
Boot буквально в процессе создания этого проекта. Он явно просил не получать
готовый код, а разбираться в каждом шаге.

**Поэтому при любой задаче:**
1. Сначала объясни, ЧТО мы делаем и ЗАЧЕМ, простыми словами.
2. Объясни, как это связано с уже написанным кодом.
3. Только после этого показывай код — и разбирай построчно ключевые
   аннотации/конструкции, а не просто вставляй блок целиком.
4. Каждый новый термин (JPA, DTO, bean, dependency injection и т.д.)
   объясняй, как будто это первый раз, когда человек его слышит.
5. Если есть несколько способов реализации — кратко опиши варианты
   и объясни, почему выбран именно этот для данного проекта.
6. НЕ пиши сразу весь фиче-модуль пачкой файлов. Двигайся маленькими
   шагами, давай автору возможность написать/повторить часть кода самому.
7. Если нужно исправить баг — сначала объясни причину (что пошло не так
   и почему), потом уже фикс. Не просто "вот исправленный код".

Если задача очевидно рутинная/механическая (например, "покажи полный лог
без обрезки", "прогони тесты", "покажи содержимое файла X") — это можно
делать быстро и по-деловому, без долгих объяснений. Объяснения нужны именно
для НОВЫХ концепций и архитектурных решений.

## Технологический стек

- **Backend**: Java 21 (проект собирается и под Java 25/26, установленные
  локально), Spring Boot 4.1.1, Spring Data JPA, Hibernate 7, Spring
  Security (ещё не подключён), Maven, PostgreSQL 16, Flyway 12.
- **Frontend**: React (ещё не начат).
- **Инфраструктура (в перспективе)**: Docker, GitHub, Jenkins, AWS
  (RDS + EC2), Nginx, Cloudflare — пока не актуально, сначала весь backend.

## Важные технические особенности ИМЕННО этой версии Spring Boot (4.1.1)

Это свежая мажорная версия с breaking changes относительно Spring Boot 3.x,
о которых мало где написано — держи в уме:

- `spring-boot-starter-web` переименован в **`spring-boot-starter-webmvc`**.
- Автоконфигурация теперь модульная (не один большой jar). Для Flyway
  недостаточно просто `flyway-core` — нужен отдельный
  **`spring-boot-starter-flyway`**, иначе автоконфигурация Flyway не
  подключается и таблицы не создаются, хотя ошибка на старте похожа на
  проблему с БД, а не с зависимостями.
- Автоконфиг-классы переехали в новые пакеты, например
  `org.springframework.boot.hibernate.autoconfigure.HibernateJpaConfiguration`
  вместо старого `org.springframework.boot.autoconfigure.orm.jpa...`.
- Если появляются странные ошибки на старте — в первую очередь проверяй,
  не связано ли это с модуляризацией автоконфигурации в Boot 4, а не сразу
  думай на конфиг/докер/сеть.

## Локальное окружение (macOS)

- IDE: IntelliJ IDEA.
- PostgreSQL — в Docker-контейнере `sup-shop-db` (образ `postgres:16`),
  порт 5432, база `sup_shop`, пользователь `sup_admin`, пароль `supsecret`.
- **Важно**: ранее был конфликт с нативным Postgres, установленным через
  Homebrew и слушавшим тот же порт 5432 — из-за этого Spring иногда
  подключался не к тому Postgres. Если снова похожие странности с
  авторизацией/несуществующими ролями — первым делом проверь
  `lsof -nP -iTCP:5432 -sTCP:LISTEN`, не появился ли второй процесс на
  порту.
- `application.properties` содержит `spring.jpa.hibernate.ddl-auto=validate`
  — схему создаёт **только** Flyway через миграции в
  `src/main/resources/db/migration`, Hibernate её не трогает, только
  сверяет соответствие.

## Полная предварительная структура БД (согласована с автором, ещё не вся реализована)

**Auth**: `roles`, `users`, `user_roles`, `refresh_tokens`

(со снапшотом цены/названия на момент покупки)

Полное описание полей/типов/связей для каждой таблицы обсуждалось отдельно —
если нужно уточнение по конкретной таблице, спрашивай у автора, не выдумывай
поля от себя.

## Тайминг и приоритеты

Автор может уделять проекту ~15 часов в неделю, цель — рабочий backend+frontend
MVP примерно за 7 недель. Поэтому:
- Не предлагай усложнения сверх текущего этапа (refresh-токены, тонкая
  настройка кэша, микросервисы и т.п.) — можно упомянуть как "на будущее",
  но не делать сейчас.
- Bean Validation и обработка ошибок — да, это часть MVP, не пропускать.
- Тесты — лёгкие, не глубокий TDD с нуля.

## Стиль кода

- DTO для запросов/ответов API, не отдавать JPA-сущности напрямую наружу.
- Слоистая архитектура: `controller` → `service` → `repository`.
- Комментарии в коде — только там, где логика не очевидна из названий.
